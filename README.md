# 临床数据匿名化发布与随访转归分析平台

面向临床研究数据管理员与数据分析员的小群体消除工具，包含两部分能力：

1. **匿名化发布**：上传含个体信息的 CSV，系统在
   **k-匿名（每组 ≥ 3 人且 ≥ 2 种病种）** 约束下自动寻找隐藏程度最小的匿名方案，
   人工确认预览后才发布可下载的匿名 CSV。
2. **随访病种转归矩阵**：选择先后两批已发布数据，按两批实际共同保留的受试者号
   配对，统计「前次病种 → 后次病种」人数矩阵；少于 3 人的格只显示隐藏标记，
   不展示可反推其人数的行列合计，全程不返回受试者号。

- 后端：FastAPI + SQLite（标准库 `sqlite3`，零额外服务）
- 前端：服务端渲染 HTML（Jinja2）+ 原生表单，无需 Node 构建
- 部署：Docker Compose，一条命令启动；数据持久化在命名卷中，重启内容不变

## 一、业务规则

### 1. 上传与整批校验

| 规则 | 处理 |
| --- | --- |
| 列：`受试者号,年龄,邮编,病种`（支持常见英文/别名表头） | 缺列整批拒收 |
| 数据行 **最多 30 行** | 超限整批拒收 |
| 年龄为 **0～99 的整数** | 非法整批拒收 |
| 邮编为 **五位数字** | 非法整批拒收 |
| 受试者号非空且 **不得重复** | 重复整批拒收 |
| 病种非空 | 空值整批拒收 |

### 2. 匿名化

- 发布数据**移除受试者号**，仅保留 `年龄,邮编,病种` 三列。
- 年龄隐藏等级：`0` 原值 ｜ `1` 十岁段（如 42 → `40-49`）｜ `2` 隐藏（`***`）
- 邮编隐藏等级：`0` 五位原值 ｜ `1` 前三位（如 10008 → `100**`）｜ `2` 隐藏（`***`）
- **最多剔除 2 行**；保留数据中每个（年龄 × 邮编）组合须：
  - 至少 **3 人**；
  - 含至少 **2 种病种**。
- 方案优选顺序：
  1. 两列隐藏等级之和 **最小**；
  2. 同级时 **剔除行数最少**；
  3. 再同级时 **优先保留年龄精度**（年龄等级更小）。
- 枚举 9 种隐藏等级组合 × 所有剔除子集（0～2 行），**无可行方案则不能发布**。

### 3. 发布与安全保证

- 必须勾选确认框、核对预览后才能发布；发布前对结果做独立二次校验。
- **再次上传后，旧的待确认预览立即失效**（状态置为 rejected），对其发布返回 409。
- 发布在单个 SQLite 事务中原子完成：发布状态、匿名 CSV 与**最终保留者的
  （受试者号, 当批病种）对应关系**同事务写入 `batch_subjects` 表；
  发布失败整体回滚，**不产生任何可下载残件，也不会出现已发布却无对应关系的批次**。
- 已发布的 CSV 以 BLOB 存入 SQLite 挂载卷，**容器重启后字节内容不变**。
- 对应关系仅用于转归配对的内部留痕，不进入预览页面，也不写入可下载匿名 CSV。

### 4. 随访病种转归矩阵

| 规则 | 处理 |
| --- | --- |
| 配对口径 | 仅按两批**实际共同保留的受试者号**内连接配对；任一批缺失的编号不参与 |
| 参与资格 | 两批都必须是 `published`；未发布或发布失败（pending/rejected）的批次拒绝参与 |
| 旧批次 | 已发布但 `batch_subjects` 无记录（功能上线前的旧批次）→ 提示**无法计算**，绝不按零人处理 |
| 一致性 | 两批的发布状态与对应关系在**同一连接、同一事务快照（同一已提交视图）**中读取 |
| 小格隐藏 | 人数 **< 3（含 0 人）** 的格只显示 `***`，不暴露真实人数 |
| 合计联动隐藏 | 含隐藏格的行合计、列合计一并隐藏；存在任一隐藏格时总合计也隐藏，杜绝反推 |
| 隐私 | 矩阵响应只含病种标签与脱敏后的显示值，**不返回任何受试者号** |
| 无交集 | 两批保留者无共同编号时提示「没有交集，无法配对」，而非展示零人矩阵 |

矩阵为行（前次病种）× 列（后次病种）的二维表，右侧带行合计、底部带列合计与总合计；
所有人数均为整数或 `***`，页面同时给出隐藏规则图例。

## 二、快速启动（Docker Compose）

```bash
docker compose up --build -d
# 浏览器打开 http://localhost:8000
docker compose logs -f web      # 查看日志
docker compose down             # 停止（数据卷 anonymizer-data 保留）
```

健康检查：`GET /` 返回 200（容器内置 HEALTHCHECK）。

## 三、本地运行（无 Docker 时）

```bash
python3 -m pip install -r requirements.txt
ANON_DB_PATH=./data/anonymizer.db python3 -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## 四、操作流程

1. 首页选择 CSV（≤30 行）→ **上传并生成匿名预览**。
2. 预览页展示：所选隐藏等级、剔除行编号、每个分组的人数/病种数校验表、
   移除编号后的匿名数据表。
3. 勾选「我已核对预览内容，确认发布」→ **确认发布**。
4. 在「已发布的匿名文件」区域下载 `anonymous_batch_<批次号>.csv`（UTF-8 BOM，Excel 可直接打开）。
5. 在「随访病种转归矩阵」区域选择先后两个已发布批次 → **计算转归矩阵**；
   人数 < 3 的格与相关合计显示 `***`，无受试者号外泄。

示例文件见 `examples/`：

- `sample_valid.csv`：可正常匿名发布；
- `sample_duplicate_id.csv`：重复编号，整批拒收；
- `sample_no_solution.csv`：仅一种病种，无可行方案，不能发布；
- `sample_followup_1.csv` / `sample_followup_2.csv`：同一批 12 个受试者号的两批
  随访数据，均含两个合规分组，可分别发布后用于演示转归矩阵（含 `<3` 隐藏格）。

## 五、测试

```bash
python3 -m pytest tests/ -v
```

覆盖：解析与整批拒收、9 级隐藏枚举、剔除上限、同级裁决规则、无解场景、
上传→预览→发布→下载全链路、旧预览失效、发布失败无残件、重启后文件一致性；
转归矩阵的共同编号配对、`<3` 小格隐藏、行/列/总合计联动隐藏、无交集、
未发布/失败批次拒绝、旧批次无法计算（不按零人）、发布事务原子留痕与失败回滚。
